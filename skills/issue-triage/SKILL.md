# Issue Triage

Use for existing reports, incoming bug queues, and turning incomplete observations into actionable investigation records.

## Triage

- Classify bug, feature, support, security, performance, documentation, or duplicate.
- Capture affected version/environment, frequency, users, scope, workaround, regression status, and reproducibility.
- Separate severity (impact) from priority (when to act).
- Search open and closed issues, recent changes, and known incidents before creating a new record.
- Identify the smallest next action: request evidence, reproduce, bisect, investigate, fix, close, merge, or route privately.
- Assign ownership only when repository rules or the user provide authority.

Do not publish, close, label, assign, or modify an issue without explicit authorization for that action. Route plausible vulnerabilities through the approved private channel.
