# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose secrets, enable
unsafe tool use, cause destructive behavior, or materially weaken an authorization
boundary.

Use GitHub's **Report a vulnerability** flow on the repository's Security tab. If
private vulnerability reporting is unavailable, contact the repository owner
through the contact method shown on their GitHub profile before disclosing details.

Include the affected skill or script, a minimal reproduction, expected and actual
behavior, impact, and any safe mitigation you have verified. Remove credentials,
tokens, private repository content, and personal data from the report.

## Scope

Security reports may cover skill instructions, installer path handling, unsafe
external mutations, prompt-injection boundaries, secret exposure, and dependency
or workflow configuration in this repository.

No response or remediation timeline is guaranteed, but verified reports will be
triaged according to impact and reproducibility.
